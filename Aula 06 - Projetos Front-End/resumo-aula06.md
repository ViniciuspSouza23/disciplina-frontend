## 1. Por que gerenciar um projeto Front-End?

Projetos Front-End crescem rápido. **Sem planejamento**, surgem problemas como:
- Tarefas esquecidas
- Requisitos confusos
- Retrabalho
- Conflitos no Git
- Atrasos
- Problemas de integração
- Dificuldade de acompanhar o progresso

**Com processo de gestão**, o projeto passa a ter:
- Responsabilidades claras
- Prioridades definidas
- Entregas incrementais
- Acompanhamento do progresso
- Redução de retrabalho

---

## 2. Gestão de Projetos Front-End

Gerenciar um projeto Front-End = organizar **pessoas, tarefas, tecnologias e prazos** para transformar uma ideia em uma aplicação funcional. As decisões precisam ser planejadas, acompanhadas e ajustadas para garantir entregas contínuas e alinhadas aos objetivos.

---

## 3. Gestão de Requisitos

Fluxo típico de um projeto:
1. **Ideia** → transformada em **requisitos claros**
2. Requisitos organizados em um **backlog**
3. Atividades **priorizadas → desenvolvidas → revisadas → testadas → disponibilizadas**

### Requisito, História e Tarefa
| Nível | Exemplo |
|---|---|
| **Requisito** | Sistema deve permitir gerenciamento de tarefas |
| **User Story** | Como usuário, quero criar uma tarefa |
| **Tarefas** | Criar formulário, criar componente, validar campos, integrar API, criar testes |

---

## 4. Gestão do Backlog

O backlog reúne **funcionalidades, melhorias, correções** e demais atividades necessárias para desenvolver e evoluir o produto. Os itens recebem **prioridades diferentes**, permitindo focar primeiro no que é mais importante.

---

## 5. Gestão de Prioridade e Estimativa

- **Priorização:** define quais funcionalidades devem ser feitas primeiro, considerando objetivos, necessidades e restrições.
- **Estimativas:** ajudam a equipe a entender a complexidade das atividades antes de assumir um conjunto de tarefas.

---

## 6. Definition of Done (DoD)

Critérios para considerar uma tarefa **realmente concluída**, por exemplo:
- Código implementado
- Testes realizados
- Revisão concluída
- Responsividade verificada
- Integração realizada

---

## 7. Scrum

Framework ágil para desenvolver produtos complexos de forma **incremental**, com inspeção frequente, adaptação e entregas contínuas. No Front-End, ajuda a:
- Organizar requisitos
- Priorizar funcionalidades
- Planejar Sprints
- Acompanhar o trabalho da equipe
